# ADR 0039: Claudia runs get an exact built-in list, a race-free /stop, pinned MCP configs

**TL;DR:** Every `claude -p` run names its built-ins exactly (`--tools=`), so tools the host doesn't know don't exist. `/stop` and the spawn share one lock and a stop epoch, so a turn queued before a `/stop` never starts. Both MCP configs are pinned by digest at start and re-checked before every run. Each run gets its own cgroup in the host unit's delegated subtree, so `/stop` kills its detached background jobs too (amendment F-C2c). KB work-tree steps run under the KB locks, the KB halt survives restarts, and `/stop` also kills a run's leader through its pidfd (amendment F-C3-2). Unit F-C2b-2 (review S-C2b host-flow-1/2/3/5); C51, C53, C58.

## Context
- host-flow-3: `--allowedTools`/`--disallowedTools` are block-lists for built-ins. A built-in on neither list (e.g. `Monitor`, which runs shell commands) was still offered, even in read-only turns, and the C59 matcher did not cover it.
- host-flow-2: `/stop` bumped the generation and killed the groups it knew. A turn still in screening (up to ~30 s) or preflight, or between `Popen` and pid registration, started after the stop anyway.
- host-flow-1: runs execute as root. The recap MCP config sits in `/var/lib/claudia-host` and was never re-read, so a turn could plant a server command that runs at the next recap with no hook.
- host-flow-5: `killpg` misses children that moved to their own session.

## Decision
- `KNOWN_BUILTINS` in `runs.py` holds the names confirmed for CLI 2.1.319 (changelog): Read, Grep, Glob, ListAgents, ToolSearch, Bash, Edit, Write, NotebookEdit, SendMessage, Agent, WebFetch, WebSearch, TodoWrite. `ToolSet.builtins` = allowed ∩ known. `build_run_argv` emits `--tools=<that list>` and refuses a built-in that isn't allowed or is an MCP name. `Task` (Agent's old name) stays in the deny lists but is never offered. Re-check the list when the CLI is upgraded.
- `RunRequest.generation` and `ClaudeRunner.kill_all(epoch=…)`: the runner checks the epoch, calls `Popen` and registers the pid under one lock. The host also re-checks generation + halt right before every run, including recap and resume turns. `WindowTracker.halt(epoch)`: a message queued earlier gets `for_message(...) is None` and leaves the halt in place.
- `pin_file` + `McpConfigPreflight`: the host and recap MCP configs are pinned (trusted owner, no g/o write, no symlink, SHA-256) and checked through `PreflightChain` after `SettingsPreflight`. Any change refuses the run and sends a `failed` alert. F-C2b-1 adds `/var/lib/claudia-host/**` (except `work/`) to the deny rules and the hook's protected paths.
- `kill_all` also signals the groups of live descendants that `/proc` still links to a run's group (fallback only, see the amendment).

## Amendment (unit F-C2c): one cgroup per run
- **Chosen:** `Delegate=yes` + `DelegateSubgroup=host` in `claudia-host.service`, not a transient `systemd-run --scope` per run. A scope would sit outside the unit (no `MemoryMax`/`TasksMax`, not killed by `KillMode=control-group` after a host crash) and needs D-Bus per run; the delegated subtree keeps runs inside the unit and needs only cgroupfs writes.
- The host runs in the `host` leaf. `delegated_cgroup_root()` reads `/proc/self/cgroup` (v2 line, segments checked) and takes the leaf's parent if it has `cgroup.kill` and is writable. Each spawn gets `run-<n>-<pid>` there: the child is moved in (`cgroup.procs`) under the spawn lock, **before** its prompt is written (`claude -p` reads all of stdin before any tool call). A failed create/move kills the child and refuses the run (fail closed).
- `/stop` and the run timeout: SIGTERM to every pid the cgroup lists, 5 s grace, then `cgroup.kill` (SIGKILL to everything left, however it detached). `busy()` follows `cgroup.events` `populated`, so a background job whose parent exited is still seen. Empty run cgroups are removed.
- `--require-run-cgroups` (set in the unit) makes the host refuse to start without the delegation. Without the flag (tests, other hosts) the pgid + `/proc` walk stays as the fallback, with a warning.
- Post-run KB commit failure (F-C2a-2 leftover, host side): `KbService.restore_worktree()` (gardener's `GitKbHistory.restore_worktree`, `*.md` only) and one fixed `failed` alert.

## Amendment (unit F-C3-2): KB locks, persisted halt, leader kill (S-C3)
- **Gardener kill order (fixcheck-a-1):** when its `claude` exits (or times out), the run's process group gets SIGTERM, a grace of at most 5 s, then SIGKILL. The MCP child commits on SIGTERM and git drops its own `index.lock`. A `.git/index.lock` left by a SIGKILL is removed only by the gardener's store while it holds the exclusive `.run.lock` **and** `.lock`: every KB git user holds one of them, so no live git can own it then.
- **Restore under the locks (fixcheck-a-2, newcode-2):** `KbStore.run_locked` runs the host's `restore_worktree` / `worktree_clean` (and the gardener's restore + revert) under shared `.run.lock` + `.lock`, waiting up to 120 s. A post-run commit that times out on the lock raises `KbBusyError`: the host keeps it pending and retries on idle ticks and before the next run. It never restores alongside the holder: the gardener's own first commit already took in everything written before it took the lock. Only a failed (or still locked) restore halts.
- **Caps (fixcheck-a-3):** `KbStore.write_admitted` runs the 2000-note / 8 MiB check under the same `.lock` hold as the write.
- **Persisted halt (newcode-1):** the halt is a marker file `/var/lib/claudia-host/kb-halted` (`FileHaltFlag`). It is read at start; an unreadable state counts as halted. `/new` restores again and lifts the halt only if `git status --porcelain -- '*.md'` is empty and the marker could be removed. Otherwise the halt stays and the reply says so. The halted reply asks the owner to fix the tree first.
- **Leader kill (newcode-4):** `kill_all` always includes runs in progress, whatever `populated()` says. Each run's leader gets a pidfd at spawn. After the cgroup kill it gets SIGKILL through the pidfd, and its pgid too while `waitid(WNOWAIT)` shows it unreaped (so the pgid can't have been reused). The final reap waits at most 10 s.
- **Approval budget (newcode-7, C46):** only created requests count: 10/h global, 5/h per window. Refusals have their own budget (30/h global, 10/h per window). Past it, a refusal answers 429 instead of its reason, so probing is still not free and a real request is never locked out by refusals. `cancel-open` of a window (`/stop`) resets that window's budgets but not the global ones, so cancelling can't lift the prompt bound. In-process; a restart resets them.

## Consequences
- A new CLI built-in stays unavailable until it is reviewed and added to `KNOWN_BUILTINS`. If a listed name is dropped in a future CLI, that tool goes missing (fail closed).
- After a tamper, every run is refused until the host restarts and re-pins. The owner gets an alert.
- Needs systemd ≥ 254 (`DelegateSubgroup=`) and kernel ≥ 5.14 (`cgroup.kill`); the target host has 255 / 6.8. Verify at deploy: the host's `/proc/<MainPID>/cgroup` ends in `/claudia-host.service/host`.
- Limitation: runs are root, so a run can still move a process out of its cgroup on purpose (write another `cgroup.procs`, `systemd-run --scope`). The cgroup catches accidental and ordinary detaching (`setsid`, double fork, re-parenting), not a root process that deliberately escapes; the C59 hook is what stands in front of that.
