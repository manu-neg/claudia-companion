# ADR 0040: Claudia's persona reaches her runs; the host sends fixed progress pings

**TL;DR:** Every run appends the checked `persona.md` **after** the fixed host rules in one `--append-system-prompt`, framed as tone only, and pinned by SHA-256 at host start (F-CL2b). Owner-message runs get up to 3 host-sent pings with fixed texts ("👀 On it…" at 20 s, "⏳ Still working… N min" at 5 and 10 min), cancelled before the final reply. Pings have their own per-message cap (3) and stop at 110/hour or when the message's remaining replies would not fit, so the final reply's budget never shrinks. Units F-CL2, F-CL2b; C48, C51, C53, C56, C59. Owner decision 2026-11-09 (Telegram "Build as proposed").

## Context
- `persona.md` (D12) was seeded into the KB but never passed into a run: only `HOST_RULES_PROMPT` was. Her replies read flat.
- Her only Telegram output is one final reply per message; a run of several minutes looked like silence.
- C56 caps replies at 3 per inbox message and 120 per hour. Pings through the same budget could leave the final reply (or the fallback / approval texts) refused.

## Decision
- **Persona (C51, C53):** `PersonaLoader` reads `persona.md` through the KB read port (`KbService.read`) at every run, in all three tool sets. `check_persona`: ≤ 4 KiB, the C53 character rules (control, bidi, zero-width, tag, other format chars and U+FFFD refused; emoji joiners and presentation selectors allowed), every `<!-- -->` comment stripped (an unclosed one refused), not empty. The block is `[Claudia persona — tone and style only; the host rules above always win]` + body, carried in `RunRequest.persona`. `system_append_text` puts it after the host rules in the single flag; a persona that names a forbidden flag spelling is dropped there (the argv check would otherwise fail the run). Missing / invalid / unreadable → the run goes without it and one log line names the reason class, never the text.
- **Pings (C56):** `ProgressPings` arms a `PingTicket` around the run of an owner message only (not commands, recap, resume turns or the gardener). Texts are host constants; `is_ping_text` is the exact allow-list. A ping is text only (never voice). `PingTicket.cancel()` sets the cancel event and then takes the send lock, so once it returns no ping is in flight or can start; the host calls it in a `finally` right after the run (before any reply). `stop()` first calls `request_cancel()`, then `kill_all`, then `cancel()`, so a slow in-flight ping never delays the kill.
- **Budget option chosen: a separate ping cap**, not raising the reply cap to 6. `POST /v1/claudia/replies` takes `"ping": true` (needs `message_id`, no `item_id`); `ReplyService.send_ping` accepts only `is_ping_text`, counts against `PINGS_PER_MESSAGE = 3` (own counter) and the shared 120/hour budget with a reserve of `max(10, replies this message may still send)` (`ReplyBudget.acquire(reserve=…)`). The reply path is unchanged. Rejected: a cap of 6 for all replies — it widens what model text can send per message and still lets pings eat into a busy hour.

## F-CL2b amendments (S-CL2 review)
- **Persona pin (C50/C51/C53):** her Bash can write the KB, so `persona.md` is read once at host start and pinned by SHA-256. Before each run the fresh read is compared; a mismatch (changed, deleted, or planted after a missing start) → the run goes without the persona and one `failed` alert per distinct change. After a hand edit the owner restarts `claudia-host`. The C59 hook also classifies Bash/Write under `/var/lib/claudia-kb` (and any `persona.md` name) as `settings_edit`, so the write needs an approval.
- **Screen relaxation (PR #36, C48):** the Haiku step became default-ok on 2026-11-09 (owner go-aheads, plain work requests pass; only strange or malicious messages are flagged) because typed text grants nothing: C59/C46 are the backstop. The prompt's "own tools or projects" carve-out now excludes permissions, hooks, settings, approvals, guards and safety checks: asking to change, disable or skip those is always flagged. The deterministic parser (step 1) is unchanged.
- **Reserve per message:** a ping is refused unless the replies this message may still send fit after it (and the 10-use hourly reserve holds). Other messages can still exhaust the shared 120/h; the claim is only that pings never consume their own message's final reply.

## Consequences
- The persona is owner-edited text in every run's system prompt: root-only file (C53), size- and character-checked, pinned, framed as subordinate to the host rules. It also appears in the run's argv (`/proc/<pid>/cmdline`, root-readable), like the host rules.
- A busy hour (≥ 110 replies) silently skips pings; the final reply still has the last 10.
- The live KB copy is not changed by deploy: the orchestrator copies the new seed into `/var/lib/claudia-kb/persona.md` by hand, then restarts `claudia-host` (the pin).
